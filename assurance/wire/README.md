# Sealed wire source qualification

The two public stdio executors implement one contract with independent source and package identities. The formal object is the state and verdict of each **actual dispatch function**, quantified over all observations of its decoded request. The observations include malformed input and time, incompatible negotiation, wrong revision, denied scope and the permitted resource. The model has positive and negative witnesses. Induction proves recovery after arbitrarily many ordinary calls.

[Contract.lean](Contract.lean) specifies expected results independently. [The translator](extract.py) derives the candidate transition tree from the Python AST and the standard Go parser, retaining branch order, every write to the ready flag and each returned verdict. It rejects syntax outside its audited fragment. The [guard dictionary](guards.json) interprets individual source expressions as decoded-input facts. Validation helpers, normalization, envelope decoding and the caller context around the binding comparison form an explicit reviewed boundary in [primitives.json](primitives.json). Those primitive fingerprints identify the trusted implementation. The actual session proof is obtained by translating control flow and independently checking the resulting proposition. Stdio loop lifts additionally inspect the LF delimiter, byte bound, EOF, unchecked notification path and reply operation. Their meaning uses the standard libraries' documented read, write and encode semantics.

[Replay.lean](Replay.lean) checks both extracted state machines against the independent contract. [Host.lean](Host.lean) verifies that the observed prior package identity, revision and pin dominate dispatch in both callers. The extracted model treats the other admission checks as independent reasons for refusal. Runtime probes plant each wrong binding, an undersized negotiated frame, wrong correlation and bad output. A delayed service must return a deadline diagnosis through both real host commands.

The [toolchain manifest](toolchain.json) records independently SHA-256-verified release archives for Linux/aarch64 and Linux/x86_64 and the hashes of their selected tools and libraries. Both archives were checked as bytes. The initial qualification executed the aarch64 tools. A receipt identifies the architecture actually replaying the proof. Install the named Lean toolchain with its standard release components and prepare the repository's locked Python environment. The toolchain is a development dependency. Its [kernel interface](https://lean-lang.org/doc/reference/latest/ValidatingProofs/) and the independent [nanoda checker](https://lean-lang.org/doc/reference/latest/External-Kernels/) both use Apache-2.0 and are distributed separately. The checker hashes the local executables and relevant shared libraries against the accepted machine build, elaborates each theorem with Lean, audits its transitive axioms, replays local declarations using leanchecker, and exports the named statements and their proof dependencies. Nanoda type-checks that exported certificate using an independent Rust kernel with only the three recorded foundational axioms. Interpreter, compiler, OS scheduling, CPU, dynamic loader, external library and clock correctness are stated trust assumptions. Timeouts are observation thresholds for this fixture.

From the repository root:

```sh
uv run --locked python assurance/wire/check.py --report out/assurance/wire.json
uv run --locked python assurance/wire/check.py --report out/assurance/wire.json --verify-artifacts
uv run --locked python assurance/wire/controls.py --report out/assurance/wire-controls.json --wire-report out/assurance/wire.json
```

The caller can set `OCS_SUBJECT_ROOT` to an independent checkout. The verifier, approved predicates, theorem statements and checker pins are loaded from the verifier's directory. Select that directory from the approved qualification edition when evaluating changes to the harness itself. The original public wire runner is read from the full Git commit `6f6e22842347806f2963ef1984d9ea592fdddaf0`. A missing Git object or tool fails qualification. A proof-only diagnostic run sets `partial` in its receipt.

Each evidence row names its atomic obligations, level and scope. The separate artifact directory contains the exact exercised Go binary, extracted Lean source, typed proof export, independent kernel output and both published-corpus reports. Artifact verification rederives the proof and rebuilds the executable before comparing. Binary identification and an observed run qualify the named build empirically. A proof of all machine-code, runtime, parser and OS semantics would require additional refinement and platform evidence.

Fault controls run in disposable copies. They remove the historical recovery case and its working index link while introducing the broken ready transition in each language, then test the fixed corpus and original theorem. Other controls change a public formula, introduce an impossible premise, remove a refusal, and substitute an artifact along with its claimed digest. Compatible reordering and an additional proved conjunct preserve the accepted guarantee.
