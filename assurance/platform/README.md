# Qualification of the reference POSIX cells

Run `uv run --locked python assurance/platform/probe.py --report out/platform.json` from the checkout. The full run checks the accepted formal assertions, extracts and compares the actual Python write fence, native admission and slot reservation decisions, and drives independently configured real cell processes. `OCS_SUBJECT_ROOT` selects another checkout. The assertion shapes and designated consuming branches come from the verifier's published checkout.

The [bindings](bindings.json) specify the claims and thresholds. The [model](Platform.lean) proves that readiness requires actual matching state, that a disabled peer leaves local authority unchanged, and that a retired epoch cannot become a writer by merely returning to the same name. Native soft-time admission refuses harder claims. Per-tenant and cell occupancy is bounded on arbitrary finite admission/release traces. The [source obligations](Source.lean) connect the exact deployed pure decisions to these semantics. Lifting uses the reviewed natural/Boolean fragment, with explicit interpreter, storage and OS trust boundaries. The complete reviewed control flow of the named consumer methods is part of the source boundary. Inserting an early write-fence bypass fails independently of the decision function. Actual atomic file replacement, handle lifetime, snapshot integrity and process loss/recovery are observed through the public interface.

The workload has two tenants, four concurrent callers, 32 warm reads, a maximum of four global and two per-tenant work slots and a five-second soft budget. Saturation returns a refusal while a separate owner and cancellation retain capacity. Raw per-read observations, comparable native measurements, first response, p95 and p99, cancellation time and cell restart time are available in the report. The two cells have separate state roots and process lifetimes. This local checkout qualifies only the named configuration. Use independent deployment evidence for a particular cluster, actual production data resilience or hardware worst-case timing.

The complete run can be split with `--mode formal` or `--mode runtime`. Individual hermetic observations may be selected with `--mode runtime --check platform.capacity`. The formal replay uses the pinned Lean 4.36.0-rc2 compiler and rechecks each compiled module with `leanchecker`. An independently implemented, pinned `nanoda_bin` also checks the exported terms for the named accepted statements. The model, source and sample measurements carry independent evidence levels.


The formal report includes the detached NDJSON certificate name and digest, the accepted declaration and the independent checker hash. All compiler/checker binaries and shared libraries must match the [approved toolchain distribution](../wire/toolchain.json). The raw proof term bundle is emitted beside the JSON report. Each `--mode formal` replay regenerates and independently verifies the bundle for the selected subject.


To verify detached submitted artifacts, run `uv run --locked python assurance/interaction/verify_artifacts.py --interaction-report out/interaction.json --platform-report out/platform.json --report out/profile-artifacts.json` from the reviewed verifier checkout, selecting the candidate with `OCS_SUBJECT_ROOT` or `--subject-root`. The verifier regenerates both accepted declaration sets and their independently checked term bundles from the selected source, checks the supplied report's scope, assumptions and exact target hashes, verifies the submitted immutable copy with nanoda, and rejects an authentic certificate from the other domain even when all reported certificate hashes are rewritten to match it.
