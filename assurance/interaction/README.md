# Interaction qualification

From the checkout run `uv run --locked python assurance/interaction/probe.py --report out/interaction.json`. The [bindings](bindings.json) identify individual claims, expected observations and the installed role. Set `OCS_SUBJECT_ROOT` to select a different candidate. The qualification process reads the publisher's models and statements from its own directory, while loading the candidate proof bodies, source and programs from the selected subject.

The Lean kernel replays the inductive invariants for unbounded traces, the constructive completion strategy for arbitrary finite output, scoped dispatch, monotone credit and cursors, terminal jobs and reconstruction of arbitrary sequences. The independent statement challenge checks exported theorem types and transitive axioms. The candidate model retains the accepted semantic definitions. Alternate proof bodies and additional theorems may preserve the same promises. New semantics need a reviewed refinement or a new edition. The [source bridge](Source.lean) proves the independently specified decisions for the Python substrate actually used by the reference. The small [translator](lift.py) accepts total Boolean and natural decisions, nonnegative constants, guarded saturating subtraction, comparisons and fixed products. The source verifier also compares the complete recognized consumer AST, including every guard, early return, assignment and overwrite. Those named wrappers are reviewed preconditions for transferring each pure decision theorem. Threading, I/O, storage and the remaining Python coverage are qualified separately through the public observations. Alternate pure decision implementations can prove equivalent; a changed wrapper control flow needs a separately checked refinement. The interpreter, SQLite serialization/durability, socket implementation and OS remain explicit trust boundaries.

Modes `formal` and `runtime` replay just the corresponding portions. Mode `stand` requires a named endpoint and an ordinary synthetic Alice capability in `OCS_INTERACTION_TOKEN`. It measures the deployed deterministic peer and drives ephemeral read, refresh, retry, review and close paths in a PTY at two effective widths. Durable job creation and effect authorization require the local named fixture and its separate administrator. The local harness cannot attest which cluster actually ran an externally supplied endpoint. A deployment owner links that observation to its authorized workload, identity and validity interval. The default mode covers separate local processes, temporary durable stores and isolated loopback traffic.

Use Lean `leanprover/lean4:v4.36.0-rc2`, compiler commit `b35cb10cf2ced51a2fd1880cfdbf75c71ab7a35a`, with the associated `leanchecker`. Each compiled module is replayed in its own checker process. A pinned independent kernel, `nanoda_bin`, additionally checks the exported proof terms for every named accepted statement. Accepted standard logical dependencies are `propext`, `Quot.sound` and `Classical.choice`. No native evaluation, new axiom or unfinished proof is admitted.


The live transcript in each applicable observation records registered method, contract/version, selected manifest digest, result/refusal/notification counts and independently validated message hashes. The mixed-generation agent case starts `reference/host.py` from the accepted commit against the actual candidate dialog process. A separate control exchanges the same request ID in two independently admitted callback directions. The model covers arbitrary finite work under rolling credit, keyed event deduplication, tenant noninterference and parallel reservation before two live child requests.

Run `uv run --locked python assurance/interaction/controls.py --report out/profile-controls.json` to apply isolated mutations to these profile and platform assurances. In particular, an early return before a stream send or a subsequent overwrite of its computed credit must be rejected by the source verifier even when the decision function itself is unchanged.


The formal report includes the detached NDJSON certificate name and digest, the accepted declaration and the independent checker hash. All compiler/checker binaries and shared libraries must match the [approved toolchain distribution](../wire/toolchain.json). The raw proof term bundle is emitted beside the JSON report. Each `--mode formal` replay regenerates and independently verifies the bundle for the selected subject.


To verify detached submitted artifacts, run `uv run --locked python assurance/interaction/verify_artifacts.py --interaction-report out/interaction.json --platform-report out/platform.json --report out/profile-artifacts.json` from the reviewed verifier checkout, selecting the candidate with `OCS_SUBJECT_ROOT` or `--subject-root`. The verifier regenerates both accepted declaration sets and their independently checked term bundles from the selected source, checks the supplied report's scope, assumptions and exact target hashes, verifies the submitted immutable copy with nanoda, and rejects an authentic certificate from the other domain even when all reported certificate hashes are rewritten to match it.
