# Binding, trust and multiple hosts

**B-01 Resolve.** The owner binds an import at composition time to a public export with exact compatible contract, package revision and scope. A binding is directional. It is independent of package installation, network reachability, discovery and feature declarations. The [assembly schema](../schemas/assembly.schema.json) describes a static assembly. An application may construct the same facts in code. Core does not prescribe a service registry.

**B-02 Admit.** Validate packages, pinned revisions, operation versions, schema compatibility and effect policy. Resolve required imports before exposing dependent operations. A sealed or validated interface can be cached. Reevaluate authorization at the point of effect. Unknown mandatory constraints, colliding identities, missing required bindings and ambiguous selection have a visible diagnostic. A test or health probe binds the exact target being reported. A successful fallback is attributed to the fallback.

**B-03 Authority.** On each hop verify the authenticated caller, package/instance, permitted import, authorized recipient/export, operation, resource and owner. A trusted service boundary supplies tenant, identity and actual target. A user message, agent response, presentation event or claimed tenant header cannot elevate that caller. A plugin may invoke another component only through an authorized public binding. A read-only grant cannot cause a reset or charge indirectly. Reject a denied operation without trying a different account. Secrets are host-brokered, scoped to authorized issuers/destinations and isolated by principal and account. Scope and revalidate access to artifacts, including on reconnect. Do not embed tokens in displays, model input or logs.

**B-04 Federation.** Peer owners decide separately which capabilities to export and import. Names are interpreted within the authenticated trust domain. A → B and B → C do not grant A direct access to C. A composite service can export its own versioned contract and execute approved dependencies internally. Preserve causal identity and enforce permitted delegation at every hop. Authenticate peer, intended audience, policy epoch or expiry, data residency and minimum necessary content. Rotation/revocation has a documented observation lag. During a partition, apply the declared offline policy. Deny sensitive actions when their required authority cannot be verified. Separate tenant state, grants, events and cancellation handles. Neither a shared root of authority nor a globally available registry is a Core dependency.

**B-05 Resilience.** Each operation names its state owner, freshness requirement, deadline, resource budget and response to partial failure. Bound depth, fan-out, retries, queue size and data volume across the entire chain. Choose one retry owner for an operation. Limit slow receivers and isolate unhealthy providers. Classify overload and upstream denial separately. Preserve local functions when a peer or optional UI fails. A peer reconnection resumes or reconciles prior operations. It must not recreate an uncertain write as a fresh one.

**B-06 Observability and evolution.** A trace correlates parent and child calls, target and actual revision, elapsed time and permission decisions. Report confirmed facts separately from stale or inferred observations. Apply retention, deletion, confidentiality and regional policy to both data and diagnostics. An application exports its public result while keeping administrative operations private. A replacement that changes consistency, identity, freshness, latency or effects must renegotiate the guarantee.

**B-07 Scale.** An implementation declares finite admission and resource limits. A composition may grow by adding autonomous hosts or cells. Publish load mix, payload size, concurrency, bottleneck, availability window and distribution of latency. Compare the invoked path with the same native operation. Test peak load, loss of a cell and a slow tenant. Shared stores, credentials and routing can correlate failures. A multi-process test does not certify arbitrary scale.

## Calling an import from inside an extension

An instance calling an import takes the ordinary caller role. The host supplies a handle or channel for the binding selected at admission. Each channel selects one authenticated recipient and scope. The instance negotiates the recipient descriptor and calls the same operation/version as any other caller. A host can implement the channel with a local function adapter, a second pipe, or a scoped authenticated endpoint. The recipient checks the effective scope again using its own authority. The endpoint is deployment configuration. Package data cannot substitute another recipient.

If a transport multiplexes calls in both directions, treat each direction as a separately negotiated session. Match responses to the originating direction and its request ID. Bound both work queues. An implementation that serializes requests must use another admitted channel for a callback which would otherwise wait on itself. An application may export a composite result while keeping its internal dependency private. Upgrading the internal implementation preserves the public result and its declared semantics.

## Deployment choices

- For a small application use one host, local packages and explicit bindings. Separate code ownership does not require a separate network service.
- Isolate third-party executable code with a supported sandbox or separate execution boundary. If requested confinement is unavailable, reject activation or require a separately documented trusted-code deployment policy.
- Across operators expose only admitted operations. Route high-volume data locally or directly through a negotiated scoped handle. Inner loops do not require a global control-plane round trip. Privileged and domain-specific native paths must retain the same ownership, safety and audit guarantees.
- For a coherent GUI, TUI and API, the service owns decisions and authoritative results, and the host owns navigation and trusted consent. See [presentation](profiles/presentation.md).
