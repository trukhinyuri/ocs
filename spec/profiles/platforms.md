# Cloud services, native components and critical paths

**L-01 Service contract (`ocs.cloud/0.1`).** A cloud product declares its resource and lifecycle operations, public API version, tenant/project authority, state owner, deployment placement and applicable dependencies. Local, remote and API-only products can implement the same semantics. Required operations declare applicability. Unsupported operations give a reason. Provision, hold/resume, resize, backup, restore, export or delete are only exposed when they actually exist. A declared resource operation returns an authoritative resource state or durable job. Reconciliation compares desired with observed state. A successful control request alone does not prove a resource is ready. Define retention and export, deletion, IAM, capacity, metering and data residency for each applicable operation. Distinguish paid, zero-priced metered and non-billable offerings. Resolve cross-product attribution and limits before incurring costs.

**L-02 Autonomous peers.** An operator can run a standalone host offline or in one cell. A cross-domain offering is opt-in at both ends. A portable [resource observation](../../schemas/profile-data.schema.json#/$defs/resource) names identity, owner, conditions and revision. Local changes remain possible during a partition if their owner and policy allow them. External writes require the owning domain, explicit reconciliation and an honest unknown state when evidence is missing. One domain must be able to revoke a peer without losing its own products.

**L-03 Platform binding (`ocs.platform/0.1`).** Publish the [platform descriptor](../../schemas/profile-data.schema.json#/$defs/platform) under the manifest extension `org.ocs.platform`. The runtime’s `adapter` is selected by verified identity and exact deployment configuration. Declare platform, target format/architecture, ABI or kernel revision where applicable, loading authority, isolation, native interface, lifetime of handles, observable faults, upgrade/recovery strategy and supported timing class. The host validates these before activation. Configuration and diagnostics can use OCS. An interrupt handler, device buffer or other hard critical path uses the platform's own admissible interface. A module with kernel privileges can affect the host itself. Reject requests requiring containment or a worst-case time bound the platform cannot establish. A statistical p99 is not a hard deadline guarantee. Demonstrate privileged admission and rejection using a simulator unless specifically authorized to use the target system.

**L-04 Performance and recovery.** Publish workload shape (requests, bytes, burst, fan-out, cache), measurement point, observation period and criteria. For interactive calls measure startup, first usable result, p95/p99 and cancellation responsiveness with sample size. For high-throughput services bound queues and measure resource and error behavior under a slow tenant, loss of a cell and recovery. Justify any optimized transport against the ordinary path with equivalent scope, revision, confidentiality and loss behavior. A topology or reference fixture gives no guarantee of infinite throughput.

**L-05 Adoption.** Existing software can expose a selected native API, command or contract through a thin adapter. Document exact mappings, missing capabilities and changed loss or precision. Preserve prior IDs, state, artifacts, account grants and explicit routes during migration. Only one implementation owns the write path during cutover. If a signature, runtime ABI, protocol major or permission is incompatible, state why. A normative profile for an additional domain requires an actual consumer, a defined failure boundary and conformance data.

**L-06 Product operation.** A service offering with commercial or operational obligations declares the plan and entitlement owner, applicable terms and expiry behavior, operator/support responsibilities, distribution channel and upgrade policy, continuity arrangements, catalog visibility and evidence freshness. Supply versioned references to the applicable policy or agreement. A billing event identifies its owner, tenant, meter, measured quantity and unit, interval, attribution and stable replay key. A price observation is distinct from an authorized charge. Duplicated or backfilled events must not charge twice. Define who can export data, restore resources and revoke a tenant or offering, and what happens to existing state. Expose the effect of missing backup capacity or an unavailable operator before promising recovery. A local, unmetered component can omit commercial obligations and identify their inapplicability when making a cloud profile claim.
