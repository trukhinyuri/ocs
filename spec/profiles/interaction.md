# Streams, events and conversation continuity

**I-01 Short path.** A one-shot read uses a single invocation and final response. A persistent job, queue, callback or conversation is optional. One owner governs retries for a call chain. Child attempts share its remaining deadline and resource budget. A speed or cost floor is useful only with stated input size, load, cache and operating conditions.

**I-02 Streams (`ocs.stream/0.1`).** A caller opting into streams supplies an initial positive chunk credit with the profile's open request. Use `stream.open {operation, version, input, credit, meta}` with normal call metadata and an admitted read or separately committed operation. For an effect-bound result, include the surviving committed `operationId`. Check the original scope, intent and permission to read. Stream the existing output without starting another write or charged generation. Each `ocs.chunk` notification carries `requestId`, `seq` (starting at 1), `kind` and `data`. `ocs.credit {requestId, add}` grants a positive bounded number of extra chunks. A producer cannot emit data without credit or accumulate unbounded unsent data. A terminal RPC result or error ends the stream exactly once. Its final summary is not an extra copy of the streamed answer. `ocs.cancel {requestId}` requests cancellation without granting permission to undo an applied effect. Bind stream controls to the authenticated caller and original request. If a transport cannot carry credits/cancellation, select a compatible binding or negotiate a bounded page of results. Never claim the same guarantee under weaker behavior.

Ignore a duplicate identical chunk for an already accepted sequence. A conflicting duplicate or gap requires resynchronization or an explicit error. Replay is available only when separately advertised with retention and a resume cursor. Chunks from earlier generations cannot advance the current stream. Bound chunk size, outstanding bytes, fan-out and idle duration. For HTTP, a negotiated streaming binding can use one event stream of JSON-RPC envelopes, with control messages on authenticated POST. Describe that binding's endpoint/correlation policy. Plain Core HTTP has no streaming claim.

**I-03 Events (`ocs.events/0.1`).** A publication carries `eventId`, `type`, source, resource scope, observation time and a typed payload or artifact reference. Specify the authority to publish, subscribe and retrieve linked content. For live UI a notification may simply invalidate a snapshot. A durable subscription additionally defines cursor, retention, acknowledgement, replay and ordering domain. On duplicate delivery suppress only an identical event with the same identity in its source/scope. On missing history, request an authorized snapshot or show a gap. No global total order is assumed. An event describing a change is not consent to initiate another. Expose `events.subscribe`, `events.ack` and `events.resume` only for the agreed delivery contract. Separate durable subscriptions from ephemeral listeners and release both according to their retention/lifecycle terms.

**I-04 Artifacts (`ocs.artifacts/0.1`).** A handle supplies an opaque ID, media type, version or digest and, where known, byte length and expiry. Reading it requires the correct owner, tenant, recipient and permitted purpose. An identifier or hash alone never authorizes the read. For large data reuse a compatible handle instead of repeating content. Send a delta only against a known base revision. Otherwise use a bounded snapshot. Report loss of modality or precision before conversion. Native handles have explicit lifetime, platform and close/revoke behavior.

Two native peers can read an artifact entirely through OCS. Bind `artifact.read@1.0.0` to its state owner and supply the pinned artifact, starting byte offset and maximum decoded bytes. The owner rechecks scope and expiry for each page and returns the same artifact, exact offset, standard padded base64 data and `eof`. Offsets count decoded octets. Enforce the caller’s byte budget and negotiated frame limit after encoding. A non-final page makes positive progress. An offset beyond the end is an input error. An offset at the end returns an empty final page. A changed revision is a pin error. Increment the next offset by the decoded size and verify declared length and SHA-256 before treating assembled content as complete. Keep a principal’s handle scoped during caching, cancellation and relay. Large content can use a negotiated native data path with equivalent bounds and ownership. [Base64 encoding](https://www.rfc-editor.org/rfc/rfc4648)

**I-05 Hooks and automation.** Hooks declare their event, phase, budget, permitted effects and ownership. An observer hook cannot modify the event. A transforming or vetoing hook is opt-in, ordered deterministically, attributed and revalidated before effect. Bound reentry and causal depth. Installing an instruction, schedule or hook never grants external-write authority. A background instance uses its own scoped identity, admission limits and cancellation. Absence of a human does not turn a proposal into an approved action.
