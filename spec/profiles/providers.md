# Accounts, quotas, prices and model coverage

A provider component owns its domain-specific adapter and mapping to public operations. The host owns secret custody, dispatch, account selection, budgets and the authoritative view consumed by clients. `ocs.providers/0.1` requires `provider.describe` to expose the product/route, supported sign-in methods, callable operations and evidence sources. Each additional operation is independently declared. Capability discovery does not test paid operations.

**A-01 Identity and sign-in.** Separate provider, product, entry method, plan, account, organization, route, model and shared pool. Give the account a stable local ID and recognizable display name. Include the upstream identity only when trustworthy. Support a schema-defined choice of API key, browser authorization with PKCE, device code, service account, signed request, managed connection or a local service with no secret as applicable. The system browser or host-owned flow handles sensitive interaction. A broker binds issuer, scopes, redirect, selected route, state and recipient, stores and rotates secrets, and validates callbacks. A plugin receives a scoped handle rather than other accounts' tokens. A new credential method is a small broker capability with explicit risks. A multistep connection can use the negotiated account continuation with its original account intent and issuer. `account.connect`, `account.reauthenticate`, `account.enable`, `account.signout` and `account.remove` have distinct effects. Disabling local routing, deleting a local connection and cancelling a paid plan are separate actions.

**A-02 Account state.** When the host or adapter owns account inventory, expose `account.list` within the selected principal, provider and product. Return a complete inventory or a partial page with opaque continuation and scope-bound revision. A partial read cannot remove known accounts or turn a count into a global total. Distinguish configured, enabled, authenticated, entitled, exhausted, temporarily unavailable, unverified and verified working. Report actual reason for denial or uncertainty, the scope, observation time and a useful next action. A verified reply names the actual account, route, model, mode and timestamp where observable. A fallback, catalog listing or successful login is not evidence for the originally requested combination. Keep full status detail behind a brief actionable summary. Bind tests to one exact account. Identify health probes separately from productive calls and disclose potential cost.

**Q-01 Quota windows.** `limits.read` returns an account-scoped set of [quota windows](../../schemas/profile-data.schema.json#/$defs/quotaWindow). Each window identifies its pool/scope, modality or model group when applicable, unit, interval, total/remaining or percent if known, source, observation time and reset time if supplied. Use exact decimal strings. Numeric zero, unlimited under terms, unavailable, stale and unknown are distinct. Percent alone cannot establish a numeric total. Show the limiting window for the selected model and display time until reset in the user's locale. A passed reset instant requires re-observation. Sum only proven independent compatible pools of the same unit, usage scope and accounting period. Count one shared pool once. If independence is uncertain, keep its windows separate.

**Q-02 Reset.** Reading limits, automatic window recovery, lifting a local retry pause and consuming a provider reset credit are different operations. For `quota.reset` declare the real upstream scope, grant ID, available count or other verified entitlement, expiry, affected windows and cost when known. Offer commit only when the account is eligible and a supported authorized route exists. Use E-02–E-04. Treat remote success and a failed subsequent refresh separately. If reset is only supported at the provider, present the verified management link. Never reset a real grant to discover whether the feature exists.

**P-03 Prices.** `plans.price` returns [plan prices](../../schemas/profile-data.schema.json#/$defs/price) by plan identity, currency, region, billing interval, seat/organization basis, tax and annual terms if known, source and date. Separate published list price, actual account price, metered API spending and per-action surcharges. Contract pricing, zero charge, not published and failed verification have different statuses. If the plan is ambiguous show the applicable choices. Do not multiply a shared organization's price by its login count. Money without an explicit currency cannot be combined across plans.

**M-01 Catalog.** `model.list` returns a complete or explicitly partial [catalog snapshot](../../schemas/profile-data.schema.json#/$defs/catalog). Name provider, product, route/account scope, revision, observation time, provenance and paging completeness. Track official listing, account entitlement, adapter support and verified reply independently. Retain the last complete comparable snapshot while pages are missing, the service is offline, or authorization changes. Compare stable model IDs and aliases within the same scope. New data for an existing protocol can be adopted after compatibility validation. Report new models and new unrecognized settings by name. A missing page or model is not an end-of-life notice. Lifecycle notices need an official source, time, effective date, replacement when known and affected choices. Deduplicate by notice identity and revision. Preserve old conversations and explicit model selection.

**M-02 Invocation.** `model.generate` declares accepted input/output modalities, structured parameters, tool support, context and output bounds, reasoning levels or budgets, speed tiers, constraints and costs as known. Expose actual native values and their mappings to standard, fast or ultrafast presentation choices only when supported. Validate the exact combination for this account and endpoint. Distinguish requested, sent, provider-confirmed and unknown. Incompatible modality or mode has a visible error. Never claim success for a combination silently substituted. Search, embedding and ranking services expose their own operation instead of pretending to answer a chat.

**A-03 Operational view.** Show counts of accounts, enabled routes, known working choices and actionable problems with their units. Group by provider and filter by the selected model or status. At one account show identity, limiting window, next reset, freshness and reversible routing switch. Before disabling the last available route, identify the affected models. For 7- and 30-day use separate real successes, active days, last use, confirmed fallback use and probes. Unattributed gateway traffic stays unattributed. `usage.read` returns scoped aggregate records or unknown, with retention, currency and observation window. Show the same facts through the programmatic interface and human clients.
