# Local provider and metered product

This sealed provider runs as a stdio process under an explicitly supplied test principal. Its local text classifier scores word occurrences against a small labelled training corpus. Account, plan, pool, catalog, confirmation and meter records belong to the local fixture database. The synthetic list price is USD 2.50 per organization per 30 days. A connected trial's observed price is zero. A reset consumes one local credit and costs zero currency units. The terms export records the entitlement owner, expiry, support and recovery procedure.

Use the repository's locked Python environment. The actor starts the reviewed process with `uv run --locked python reference/provider/executor.py --store /tmp/ocs-provider.db --principal reader`. Exchange `ocs.describe` and `tool.call` with the manifest pin. The scoped managed-ticket fixture completes through `account.continue` using an opaque handle minted by the separate trusted operator. The alternative local sign-in uses no secret. Account removal archives local routing while retaining its audit trail and entitlement. A sign-out withdraws authentication. An operator may restore the entire backup in a separate directory under the original access policy.

The public `example.account.overview` and `example.product.terms` operations export the same values as the operator CLI. The human overview uses plain text readable from a terminal. `effect.prepare`, `effect.commit` and `effect.readback` address an exact account and reset intent. Approval is an out-of-band operator action. In the external-acknowledgement-loss fixture the first commit reserves the credit durably and delivers to a second local database. Retrying is read-only. A trusted reconciliation matches the independent authority's operation ID, intent digest, principal and account. The reservation is retained for the database lifetime.

The database owner may take a coherent SQLite backup with the separate administrative CLI. A whole-store backup is privileged maintenance. Reads and exportable product/usage observations on OCS channels remain principal-scoped. Backfilled meter data uses the same owner, account, meter, interval and event key. Ingesting it records an already settled synthetic observation. Passing a caller-controlled field cannot turn this into an external charge.

The interpreter, SQLite transaction/durability behavior, cryptographic primitives, clock and fixture dispatch boundary are trusted dependencies. The standalone qualification runs actual separate processes and preserves explicit evidence of the selected route. See [the acceptance criteria](../../assurance/provider/criteria.json).

The account overview accepts optional provider, model, status and time-zone fields. It displays the limiting applicable request window, local reset instant and remaining seconds for the selected model. It calculates last-route impact across all admitted connections of the owner before display filters are applied. An unresolved organization plan exposes its applicable published choices and retains an unknown account price until fresh billing evidence identifies it.

A user can save an exact route, model and settings with `example.model.select`. `example.model.selection` reports any applicable official lifecycle notice with the affected selection. Explicitly retained exchanges use `example.conversation.exchange` and `example.conversation.read` in an account-owned context. Catalog refreshes preserve prior selection and completed turns. Sending under an unavailable selection yields a scoped refusal.
