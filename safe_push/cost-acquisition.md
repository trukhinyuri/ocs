## Elect the workload

At initial enrollment choose the external incumbent source commit and independently review its files, the target, historical claims and measurements, and all retained contrary findings. Register the exact reviewed bytes of `cost_acquisition.py` as a predicate checker confined to `evolution/receiver-cost` and `policy/receiverCost`. The role grant has the following form.

```json
{

  "requirements": ["evolution/receiver-cost"],
  "pathPrefixes": ["policy/receiverCost"]
```

Acquire the source identity using `operator_cli.py cost-source PROTECTED_CHECKOUT FULL_INCUMBENT_COMMIT`. It compares the actually installed receiver, scope helpers, solver semantics, proof-tool manifest, worker and collector to their Git bytes. Use `cost.py platform` to identify the selected Linux measurement platform. For a production release obtain `operator_cli.py cost-context` under the actual native publisher's operating constraints. It identifies the interpreter, process IDs and groups, relevant privilege controls and visible network interfaces. The receiver checks the declared native context during both acquisition and subsequent execution. Hardware, thermal state and independent physical observation retain their declared external assumptions.

Before measurements, freeze a canonical JSON workload with format `ocs.safe-push.cost-protocol/1`. Supply `incumbentRevision`, `incumbentSourceSha256`, `platformSha256`, and, for a full OCS release, `executionContextSha256`. Under `conditions` describe the exact `target`, `workload`, `cache`, `concurrency`, `observer`, `uncertainty` and `exclusions`. The `ceilings` field selects either `first-eligible-observation` or an independently chosen upper bound for each of the seven protected cells. A first sample that violates a predeclared bound creates a retained refusal.

## Elect the first registration

A successful command prints `registration`, `artifacts` and `proofBody`. Use that exact registration in the proposed policy. Stage the publicly inspectable content-addressed artifacts using `operator_cli.py evolution-input` from the journal's `objects/DIGEST` files and bind their digests in the proposed evolution subject.

| Artifact | Independently checked content |
| --- | --- |
| `costProtocol`, `costPlan`, `costSource` | The original workload, dated authorizations and incumbent's Git file identities |
| `costGenesis`, `costReceipt` | The original unchanged ledger and the complete verified, unpublished PREPARE result |
| `costReviews` | Original signed review bytes, immutable inventory and applicable remediation materials |
| `costObservation`, `costOutcome` | Original counter samples, their seven derived values and the incumbent's authenticated result and ref readbacks |

Use the returned positive proof body in an `evolution/receiver-cost` artifact. A distinct refusal body can assert one different measured value. The old-purpose checker reads the bound artifacts, verifies signatures and originally applicable times, reconstructs the complete finite input witness, and re-derives all seven measurements from the two raw snapshots. Candidate-supplied executable code is outside its interface. The native receiver additionally reconstructs the independent Lean proof against the original ledgers. Approve the exact evolution under both quorums using the existing `rotate` workflow. [Evolution signing and controls](evolution.md)
