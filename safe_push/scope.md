# Scope of a Safe Push change

The receiver derives the change from the authenticated Git trees of the published parent and proposed child. The enrolled guardian supplies the classification rules, normative checker and public case interpretation. A transition produces a review plan even when every mechanical comparison succeeds. Admission also requires the exact qualification, proof and review evidence in that plan. [Coverage rules](coverage.json) · [Admission procedure](admission.py) · [Proposal](../proposals/safe-push.md)

## Object and subject identities

The receiver reads the commit, trees and blobs through Git's object database, including the incoming object directory supplied by receive-pack. It checks each object's Git hash and records its SHA-256, byte length, type and original mode. Paths come from raw tree bytes. Empty directories, executable bits, link targets and tracked files matched by ignore rules remain visible. Sorting, UTF-8 representation, portable name collisions and enrolled size bounds are checked before classification. `safe.directory` is scoped to the verified repository path. The inventory reads candidate hooks, filters, packages and source as data. [Inventory implementation](scope.py)

The clean OCS report's subject has four fields, `revision`, `dirty`, `treeSha256` and `fileCount`. Its digest covers the sorted map of regular file content hashes, including safely resolved in-tree file links. Separately, `wholeTreeSha256` covers the entire typed inventory. An executable-bit change can preserve the first digest and changes the second. The decision binds the commit identifier and both trees. The external target of a gitlink or large-file pointer requires an independently enrolled acquisition method. This guardian returns `undetermined` for these objects, dangling or external links, undocumented types or exhausted acquisition budgets. ## Stable requirements

`change_requirements(repo, parent, candidate, old_inventory, new_inventory)` rereads the inventories from the exact commits, checks all old and new objects, and returns ordered per-path changes. Each entry names the change, the original and proposed typed objects, applicable categories and requirements. Directory identifiers account for subtree changes. A separate requirement digest binds the trusted coverage policy, both commit identifiers, the full change set, affected paths, claims, criteria and semantic changes.

| Requirement kind | Responsible party | Evidence for this transition |
| --- | --- | --- |
| `qualification` | Enrolled verifier | Genuine replay for the affected implementation and the enrolled targets, old consumers, public cases, deployed hashes and exact atomic evidence levels. OCS full qualification covers the named catalogue. A calibration target has its own population. |
| `portable-proof` | Enrolled independent checker | A machine-checkable artifact for the claim and subject. The existing checker must establish semantic preservation, source or binary refinement, non-interference or a valid guardian transition as requested. |
| `domain-review` | Accountable domain authority | Signed criterion-specific findings, sources, method, falsifier, affected population, original commitments, contrary results and applicable evidence under that domain. |
| `independent-review` | Separate reviewing authority | An independently signed check of the specified evidence, reproduction, remaining disagreements, risks or platform coverage. |

Each requirement carries machine-readable evidence facets. The receiver authenticates the role and ties the submitted material to the requirement digest and exact candidate. It checks the actual qualification or verifies the portable proof whenever that kind applies. Purely editorial wording uses reviewed sources and full existing qualification. A change in an executable contract, program or binary requires its corresponding preservation or refinement evidence. Equal decoded JSON, a normalized line ending and an edit wholly within an identified informative Markdown section have narrowly recognized editorial treatment. A new theorem in an enrolled sealed proof language can retain the prior semantic declarations and propositions. The existing kernel replay still covers the published challenges. Scientific and safety applicability receive explicit dispositions at every substantive changed path. [Requirement templates](coverage.json) · [Claim-specific validation](admission.py)

## Continuity and decisions

The published scenario index, public positive and refusal transcripts, rule attribution, atomic obligations, required evidence levels, control identifiers and observed-check attribution establish the parent commitments. The guardian preserves the ordering, exact request inputs and old expected results in published transcripts. It checks normative paragraphs, schema constraints, registered operations and profile fields with the enrolled declaration inventory. An edited executable tester, guardian, trusted input or recognized semantic change sets `policyChange` and requires verification and approval under the incumbent authority. Register a genuinely new object interpretation separately before admitting commits that depend on it. [Normative comparison](../assurance/structure.py) · [Release evidence rules](../assurance/trust.py)

The plan records stable atomic claim IDs. Transitive effects default to the whole enrolled contour. A directly attributed prose review can also use the published rule-to-document mapping. Newly declared atomic obligations and their required levels enter the full qualification inventory. Missing independent evidence leaves the decision `undetermined`. A recorded incompatible loss raises `ScopeError` with `outcome == "rejected"` and identifies the missing case, rule, required level or control. The receiver retains the published parent in either case. Each claim is scoped to its enrolled targets, semantics, assumptions and data. Expanding those conditions requires fresh evidence and applicable approvals.

Run the scope controls with `python -m unittest discover -s safe_push -p test_scope.py -v`. The controls use disposable local object stores. They replay the deleted `recover-after-input-error` case from its historical edition, weaken the exact expected refusal, remove a protected control, change an executable tester, check ignored and unknown objects, and verify quarantine visibility through the public inventory interface. Positive controls exercise a strengthened transcript, an additive theorem, an additional claimed capability, source equivalence classification and ordinary editorial changes. Scope controls establish the required evidence and rejection behavior. A candidate's actual publication also requires the separate receiver and qualification checks.
