# Qualifying a sealed OCS execution

The receiver uses `inspect_dossier(dossier, enrollment, observer, checker_repo, verifier, subject)` for the `ocs-dossier/1` target. The authority supplies the full verifier commit, public observer key, independent stand enrollment and expected clean Git identity. The Git object store must contain both commits. A bare repository and incoming objects in the pre-receive quarantine are supported.

The verifier snapshots regular files and rejects links, pipes, duplicate JSON members and unlisted artifacts. It authenticates the complete aggregate and the stand attestation separately with the enrolled Ed25519 key. It runs the enrolled edition’s stand verifier and reconstructs its obligation matrix from the detached family reports. Source data comes from the named Git objects. Only the enrolled checker supplies executable code. The signed aggregate attests the earlier execution of the theorem kernels, physical experiments and mutation controls. Offline inspection verifies their recorded inputs, results and signatures.

For the historical edition, acceptance covers 394 required levels of 245 promises, 64 numbered rules, 31 scenarios, 11 profiles, 2,940 normative declarations, 326 witnesses, 66 controls and 24 signed detached artifacts. The operation matrix is committed by the signed interface report. Normative declaration entries are regenerated from Git. The three auxiliary public-case reports have unsigned timestamps and formatting. Their exact case IDs, rules, outcomes, role, target, corpus and scope are checked against the authenticated corpus and execution interval. They supply no quantitative measurements to the receiver.

## Comparing the observed workload

The independently installed [metric profile](metrics.json) fixes the member identities, sample counts, direction, units, measurement points and environment inputs for each metric. Each cell contains an exact decimal value, a direction and a digest of its experiment conditions. Lower values improve latency, bytes, charges and resource demand. Higher values improve completed work, verified quality and throughput. Quality, throughput and cost remain independent comparisons.

| Population | Signed results used for comparison |
| --- | --- |
| Deployed provider, direct and two relay modes | Correct tasks, model tokens, client and upstream JSON bytes, synchronous first useful and end-to-end p50, p95, p99 and maximum |
| Deployed route and storage | Load samples, native and bound read samples, cancellation, backup and restore footprint, restart elapsed time, observed plan price and charged workload |
| Presentation | Each enrolled browser viewport’s overflow, focus return and keyboard operations, plus each terminal width’s overflow |
| Local provider and agents | Sealed classifier scores and latency, native/transit body sizes, local confirmation, probe and workload charges |
| Local platform and wire | Each retained capacity sample, native and admitted aggregate rates and tails, independent neighbor and restart observations, timed public refusal paths |
| Qualification | Elapsed time for the full contour and bytes in the named generated certificates, source evidence and Go executable |

Every retained observation of a repeated, identical capacity read has its own rank. Comparing all ranks includes the slowest request and every recorded outlier. Trial position is used for the fixed browser viewport sequence. Modes, named paths and distinct operation types have separate cells. A missing member, shortened raw vector or changed numeric observation inventory creates a required `metricGap`. The receiver keeps unrelated unaffected cells available for diagnosis. Fields that describe a forced failure, scope, configured resource limit, clock timestamp, identity or protocol state serve as conditions or behavioral evidence. They carry no intrinsic preference for a larger or smaller value.

The stand condition digest binds the enrolled verifier, observer toolchain, cluster UID and version, namespace, selected node, storage class, volume and resource settings, organization, owner and plan. Each receipt independently binds its actual image, pod, volume and TLS identities. Each metric also binds the task, method, mode, units and applicable fixture conditions. A target policy enrolls the computed `targetConditionSha256`. A changed target, treatment or measured population requires an explicit comparison decision.

## Scope and tests

`coverageLimits` identifies quantities absent from the historical execution, including operator CPU, peak memory, energy, full wire traffic, raw per-task inference vectors, statistically paired trials and measured human effort. An authority that requires one of them enrolls the measurement and supplies evidence for both compared revisions. A signed observation of sampled latencies supports comparison of those executions under the recorded conditions. Population-wide performance and future behavior require their own evidence.

Run the adapter tests from the repository root.

```sh
python -m unittest discover -s safe_push -p test_qualification.py -v
```

The hermetic tests generate a disposable signing key. Historical acceptance tests use the operator’s existing enrollment at `out/acceptance/3facf571` and a preserved signed run under `out/qualification/full`. They check the original time window and test expiration separately. Production admission always uses the receiver’s current clock. The stand key establishes observed execution identity. Change acceptance and owner review have separate authority records.
