# Safe Push

Safe Push certifies one Git transition from an enrolled parent to an exact single-parent commit. The receiver makes its decision at the server's prepared reference transaction. Contributors use ordinary Git. The same rule applies to changes to the receiver itself. The [proposal](../proposals/safe-push.md) and [acceptance criteria](criteria.json) preserve the distinction between implementation, independent evidence and claims that remain open.

## Run the acceptance suite

Use a full clone that includes the draft protocol and proof revisions. Install the locked Python environment and the [pinned proof tools](proofs.md). On the native Linux qualification host the receiver experiment also needs Git, OpenSSL and an unprivileged user namespace runtime. It runs the four-frame program in an isolated read-only filesystem without release credentials or network access.

```sh
uv sync --frozen --offline
UV_OFFLINE=true GOPROXY=off make check-safe-push
UV_OFFLINE=true GOPROXY=off make check
```

The local suite uses disposable technical identities. It sends real Git pushes, reads the remote ref independently, and tests rejection, qualified improvements, concurrent candidates, contrary evidence, remediation and recovery. The qualification of a specific Kubernetes service uses a separate, independently enrolled pair of full dossiers. `test_live_receiver.py --help` lists the explicit inputs to the strict before/after receiver experiment. The ordinary project test command operates on local fixtures. See the [claim and measurement catalogue](qualification.md) for the exact 394 historical obligations and the registered comparison cells.

For full qualification, `make qualify` also opens the retained original signed dossier and independently enrolled public target under `OCS_SAFE_PUSH_HISTORY`. Set this variable to the operator's directory containing `out/qualification/full/runs/` and `out/acceptance/3facf571/{independent-enrollment.json,observer.pub}`. A fresh operator can qualify the pinned base in an independent clone, run the [live enrollment procedure](../assurance/verify-receipt.md), and retain those public artifacts in the same layout. Every required test in the selected suite must execute. The historical suite holds when the independent artifacts or the required local UID boundary are unavailable.

## Enroll an authority and operate a receiver

The owner obtains the receiver implementation revision, seed commit, checked toolchain, qualified deployment and distinct public identities through a separate trust decision. Select an operating identity for publication, a domain reviewer, an independent reviewer and the guardian of the policy. An OCS release root must enroll the full OCS qualification adapter. A receiver experiment has a visibly different receipt profile. The hosted bridge checks the release profile.

`operator_cli.py install` takes an independently chosen full source revision for the initial branch, the policy JSON, raw public observations in one directory per target, enrolled public observer keys, immutable method implementations and the publishing credential. A queryable source Git repository must contain the protocol baseline, assurance oracle and candidate objects. The initial issuer keys come from public registration. Signing endpoints, private keys, write authority, the independent epoch checkpoint and a recoverable audit copy stay in operator custody. Use `operator_cli.py install --help` and follow the [native installation procedure](local-install.md) for OS-level separation, private socket activation and permission readback.

The operator validates the typed genesis before enabling the endpoint. Its external configuration pins the root and genesis digests. `receiver.py audit CONFIG` reconciles a durable pending intent against the actual ref and checks the signed chain. `receiver.py consume CONFIG` additionally requires current applicability, freshness, absence of unresolved contrary evidence, registered receiver costs and independent replay of the actual decision packets. The current ref is read under the publication lock. An audit of the historical custody chain can succeed while current consumption is suspended.

## Submit a change

1. Supply the local evaluator with the candidate Git objects using `operator_cli.py object CONFIG REPO COMMIT`. The command imports objects without publishing a ref. Only a single direct child of the independently read canonical parent is eligible.
2. Run the previously admitted verifier in the target's protected evaluation environment. Use the full OCS release dossier for each required target and an independently obtained enrollment. The candidate cannot supply its own observer identity or choose a weaker evidence profile. Register **every** trial with `operator_cli.py stage CONFIG evidence COMMIT DIRECTORY --target NAME`. An OCS trial directory contains `dossier/` and `enrollment.json`. The custodian preserves all raw bytes and records definite adverse results even for a candidate never submitted. A later repeat or a new commit with identical contents cannot erase them.
3. Obtain the actual change map with `receiver.py scope CONFIG PARENT COMMIT` and its evidence-bound context with `receiver.py context CONFIG PARENT COMMIT`. Independent domain and assurance reviewers answer every applicable facet. Each facet points to actual immutable material, affected paths and claims. Purely editorial changes still need a substantive purpose and scoped review. Scientific and hazard claims require the applicable data, falsification, independent reproduction, target qualification and judgement described in the [scope contract](scope.md).
4. Submit separate signed `domain.json` and `independent.json`, their content-addressed `findings/` and `materials/`, and any required independently replayable artifacts using `operator_cli.py stage CONFIG reviews COMMIT DIRECTORY`. A renewal signs the previous bundle digest in `supersedes`. The historical bundle and adverse findings remain available. For a change of protected behavior or of the verifier, the old policy selects a purpose-bound portable checker and the guardian signs the transition. A failure to supply its checked translation, exact artifact, scope or other required premise keeps the ref at the parent. The fixture keys and fixture predicates in the tests are only for the named receiver experiment.
5. Push the exact admitted object to the socket or independently configured forced Git service and read the remote ref. Reference enrollment and installation must be complete before this step. If two candidates share a parent, only the candidate certified against the actual parent can publish. A new integration commit needs its own evidence and approvals.

A raw adverse measurement rejects that candidate if its protected condition and unit agree. Missing measurements, new or unsupported platforms and divergent measurement semantics hold the candidate. Protected costs include the signed OCS run duration and the receiver's own pre-publication interval. [Verifier cost protocol](cost.md) · [Mathematical decision and replay](proofs.md)

`operator_cli.py alert` registers an independently authenticated counterexample with its reproducer. Affected descendants require an old-policy replay of the proposed repair and linked approvals. `operator_cli.py rotate` applies an old-and-new authorization chain to custody key rotation. A broader change requires a separately verified [policy transition](evolution.md). Stage its independently chosen public inputs with `operator_cli.py evolution-input` and supply its signed record to `rotate`. An independently stored checkpoint can be advanced using `operator_cli.py checkpoint` and two signed readbacks of the actual published commit. Recovery from above the trust boundary requires independently authenticated backup and re-enrollment.

The pre-receive hook returns attributable refusals through the Git protocol. A success at this phase creates a signed, transaction-specific preflight under the single writer's lock. The prepared reference hook compares the exact parent, candidate, tree, epoch, transaction and deadline before it writes a durable intent. The consumer reconstructs the tip's currently applicable evidence from the sealed objects and independently replays the certificate. This also detects damage to a current review artifact after publication.

On the native installation the Git publisher cannot execute submitted programs or relax its own sandbox. A second locked identity executes only independently registered methods. It receives bounded data and, when needed, a hash-checked Git view of the selected quarantine objects. The worker can read neither publishing keys, the journal nor the external checkpoint, and cannot change refs. Kernel peer credentials authenticate both endpoints. The public Git transport never accepts method execution requests. A separate diagnostic exercises the actual four-frame status example and cannot authorize publication.

## Hosted repositories and guarantees

When the initial successful verifier cost has not been measured, retain that gap and enroll the independent first-cost method before sealing the operating policy. A single prospective, approved replay records its exact PREPARE receipt, collector inputs and original counters. A refusal records the contrary evidence and cannot supply the first successful baseline. The public operating catalogue captures the owner's real technical key registrations, historic qualified comparators, previous contrary evidence and remaining duties. Catalogue preparation alone does not initialize a canonical branch. [First-cost acquisition](cost-acquisition.md) · [Operating catalogue](operating-catalog.md)

A public or private source repository can carry review branches while canonical publication is suspended. The owner independently pins the repository and owner IDs, visibility, staging ref and permissible initial object. A hosted branch is qualified only when the independent App, live enforcing rulesets, elected writer, expected parent, exact final object and positive and negative ref readbacks agree. The original enrollment format retains private-only checking. [Hosted installation and readback](forge.md) · [Register the two technical Apps](forge-apps.md)

One human can own the project and both private App registrations. Store the technical check and publish credentials under different principals and enroll only the selected repository. Distinct App keys prove technical separation. Independent replay supplies evidence for machine-checkable claims. Each claim requiring independent human judgment, permanent custody or a comparable measured cost has its own acceptance condition. An owner's consent to host public source does not turn an unresolved claim or an adverse measurement into an approved release.

The enrolled publishing App may transfer an independently identified source commit to a newly approved review ref while canonical writes remain frozen. Its review command verifies the historical parent, consumes the public administrative rule readback and checks the actual resulting remote Git object. The default branch, enrolled staging ref and canonical ref are excluded from review destinations. [Review publication](forge-stage.md)

Before production enrollment, an active zero-bypass hold can cover the literal canonical ref even when the ref does not exist. A denied real push and a subsequent absent-ref readback establish this hold. Hosted activation also requires an authorized positive transition. A previously qualified full dossier can supply a truthful failed check on a staged commit when the protected comparison regresses. Set `OCS_HOSTED_REFUSAL_HISTORY` to the operator's filed comparison to include that replay in `make qualify`, or run `make check-safe-push-hosted-history` separately. An expired observation stays in history and cannot support a new current release claim. [Hosted refusal checks](forge-refusals.md)

The machine-checked decision uses previously enrolled semantics and finite evidence. Its soundness theorem has explicit assumptions about the mapping from signed evidence to facts, key custody, clocks, Git's ref lock, the operating system and durable writes. Counts of passing checks do not establish previously unspecified behaviors. Enrollment of a new physical target requires its own evidence. Claims about a particular critical application need its independent hazard analysis and safety authority. The universal claims from the proposal remain explicitly recorded in `criteria.json`.

The native receiver checks the pre-publication interval. A crash after writing the intent can lead to either recorded outcome. Git's actual ref decides which. Service availability, scheduling, network delivery, hardware faults, write acknowledgement after the final ref operation, disaster recovery across administrative domains and an authority's accurate scientific judgement retain their own qualification boundaries. Use currently enrolled public keys and checkpoints when consuming a receipt outside the receiver.
