# Receiver verification cost

Safe Push measures the incumbent verifier in the fresh process that evaluates an update. The interval starts immediately before `admission.prepare` and ends after it returns a verified decision, before the receiver signs and commits the ref. The receiver records a refusal before publication. Queue wait, receipt signing, journal and ref persistence, acknowledgment, post-CAS recovery, simultaneous-client throughput and remote worker consumption have separate observation boundaries. An operator with a requirement on any of them needs a separately enrolled measurement. The OCS qualification dossier already measures its own earlier wall-clock interval. [Receiver](receiver.py) · [Full qualification](qualification.md)

## Measured cells

All seven cells use integer values and a minimization order. Each candidate value must be at most both its registered ceiling and the previously accepted observation on the same measurement population. A one-unit increase over either comparator is a regression. The receiver stores the full adverse observation for the Git tree before returning the refusal. A later trial records its own values. The earlier adverse observation continues to hold admission for that tree. The observation-only experiment records measured values and has a separate status.

| Cell | Population and unit |
| --- | --- |
| `wallNs` | Nanoseconds between the verifier's two monotonic clock readings. |
| `selfCpuNs` | Nanoseconds of process CPU across its threads, sampled at the two boundaries. |
| `waitedChildCpuUs` | Change in accumulated user and system CPU microseconds of reaped children, including descendants whose intermediate parents waited for them. |
| `selfPeakRssBytes` | Lifetime high-water RSS of this fresh verifier process up to the second boundary. |
| `largestWaitedChildPeakRssBytes` | Largest lifetime RSS of an accounted child up to the second boundary. An aggregate concurrent memory claim needs an additional observer. |
| `inputBlocks` and `outputBlocks` | Changes in the kernel block-I/O operation counters of the verifier and its waited children. Byte throughput needs a separate collector. |

The Linux observer converts the kernel's RSS from KiB to bytes. It stores both samples and their read-window widths. The platform identity includes the collector bytes, clock implementation and resolution, runtime, kernel, architecture, machine and CPU identities, scheduler, affinity, ancestor cgroup controls and visible CPU-frequency policies. The full observer currently requires Linux with visible cgroup v2 controls and waited-child accounting. Missing counters, pre-existing or outstanding children, a different platform, or a change between sampled platform identities leaves canonical comparison undetermined. Elapsed time and CPU on this execution supply observations within their clock resolution. A prediction for future executions requires independent evidence about scheduling, contention, cache state, thermal conditions, repeatability and the selected workload. [Linux resource accounting](https://man7.org/linux/man-pages/man2/getrusage.2.html) · [Python clock interfaces](https://docs.python.org/3/library/time.html) · [Python resource interfaces](https://docs.python.org/3/library/resource.html)

## Independent enrollment

Seal the workload protocol before measuring. Identify the installed checker, accepted release and evidence, cache and concurrency policy, target, identity responsible for observation, uncertainty and any registered exclusions. Save its SHA-256 independently.

1. In the receiver's operating environment run `python -I safe_push/cost.py platform` to inspect its platform digest and units.
2. Restore the independently qualified receiver snapshot to the historical parent with the actual transition and its complete evidence available. Use a fresh process in the enrolled service and scheduling environment. Run `python -I safe_push/cost.py baseline --config RECEIVER.json --parent PARENT --candidate CANDIDATE --workload-sha256 PROTOCOL_SHA --output baseline.json`. This acquires the publication lock, calls the installed verification entry, binds the successful receipt and writes the canonical observation once. The command prints its file SHA-256.
3. The responsible authority independently verifies the acquisition, then enrolls `platformSha256`, `workloadSha256`, `baselineEvidenceSha256` and an integral `ceilings` entry for every named cell under `ocs.safe-push.verifier-cost-policy/1`. The baseline file uses the canonical JSON encoding generated by the acquisition command. The authority selects and owns the actual ceiling values. Reproduce the conditions that matter to the workload, including any independent controls needed for remote workers.
4. Preserve the original enrollment and the parent receipt's `receiverCost` through subsequent admissions. `finish_cost(start, registered_profile, previous_cost)` returns the current observation or raises `CostError` with its outcome, criterion and raw observation. A release without a matching registered reference and complete comparable cells stays undetermined. A separately selected `receiver-experiment/1` may use the explicit `observation-only` mode.

Run `python -m unittest discover -s safe_push -p test_cost.py -v` for the comparator controls and an actual waited-child measurement. [Implementation](cost.py) · [Executable controls](test_cost.py)
